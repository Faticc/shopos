# ShopOS 2

Машина OpenComputers, на которой нет ничего, кроме магазина. OpenOS не нужна:
BIOS грузит `/init.lua`, тот поднимает магазин и держит его запущенным.

## Как торгует игрок

1. Встаёт на PIM — магазин узнаёт ник и показывает его счёт.
2. Кладёт в инвентарь монеты `customnpcs:npcMoney` и жмёт **ПОПОЛНИТЬ** —
   монеты уходят из инвентаря в МЭ, на счёт ложится их стоимость (1 монета =
   1 $ при `coinValue = 1`).
3. Ищет предмет: просто печатает на клавиатуре — буквы сразу идут в строку
   поиска в шапке, с любого экрана. Под поиском вкладки модов с числом
   найденного, как в поиске картинок: «Все 5 · BuildCraft 3 · Minecraft 2».
4. Открывает товар, ставит количество (±1/10/64 или МАКС), жмёт **КУПИТЬ** —
   предмет приходит из МЭ в инвентарь, со счёта списывается цена.
5. **СНЯТЬ** — деньги со счёта обратно монетами из МЭ (±1/10/64/640 или
   МАКС: сколько хватает на счету, есть в магазине и влезет в инвентарь).

Продажи магазину и обменников нет.

Клавиши: Backspace — стереть букву (на карточке — назад), Esc — очистить
поиск (на карточке — назад), PgUp/PgDn и колесо — страницы, колесо над
вкладками — листать вкладки.

## Откуда товары и цены

* **Товары** — всё, что лежит в МЭ-сети под PIM, кроме самих монет. Вещи с
  NBT (броня и инструменты Draconic с энергией, зачарованное) — каждая своей
  карточкой с пометкой «особый экземпляр», выдаётся по полному отпечатку
  ровно она, по цене обычного предмета из выгрузки. `sellNbt = false` в
  конфиге их прячет. Витрина перечитывает МЭ при входе игрока, после покупки и раз в
  30 секунд.
* **Цены** — поле `min` из выгрузки цен клиента (`dumps/prices.jsonl`).
  Предмет, которого в выгрузке нет, не продаётся. Цена штуки в монетах —
  `min × rate × markup`; `rate` и `markup` правятся в `cfg/shop.cfg` без
  пересборки каталога. По умолчанию `rate = 1`, один в один с выгрузкой:
  алмазная кирка 1.50 $, алмаз 0.50 $, земля 0.00004 $.
* **Иконки** — 32×32 пикселя (32×16 ячеек), только полублоками: каждый
  пиксель своего цвета, без брайлевого зерна. Источник — выгрузка мода
  iconexporter, собранная в `assets/shop32.bin`. Если у мета нет своей
  иконки, берётся иконка соседнего.

Цены и иконки — один каталог на 5.4 МБ (6202 предмета с ценой). На диск
3-го уровня (4 МБ) он не влезает, поэтому лежит двумя частями:

| файл | где | размер |
|---|---|---:|
| `/data/catalog.bin` — индекс, цены, названия, первые иконки | загрузочный диск | 2.6 МБ |
| `/data/catalog.2.bin` — остальные иконки | второй жёсткий диск | 2.9 МБ |

RAID не нужен: магазин сам находит вторую часть на любом диске машины. Нет
второго диска — торговля работает, но часть иконок покажется «?», а в
подвале будет красная подсказка.

Собрать заново после новой выгрузки цен (обе части разом):

```bash
python tools/shopcat.py "C:\Users\User\McSkill\clients\Industrial_1.7.10\dumps\prices.jsonl" assets/shop32.bin shopos/data/catalog.bin
```

`assets/shop32.bin` пересобирается из выгрузки iconexporter:

```bash
python tools/packshop.py "C:\Users\User\McSkill\clients\Industrial_1.7.10\icon_exporter" assets/shop32.bin --size 32 --halfblock
```

## Деньги

Счёт игрока — `/var/wallet/<ник>`, целое число в сотых долях монеты.
Дешёвое стоит доли сотой, поэтому округляется только итог покупки — вверх,
не меньше 0.01 $, но хвост меньше 0.05 сотой не считается: кирка за
1.50028 стоит 1.50 $, 64 земли — 0.01 $, а не 64 × 0.01.

Все операции пишутся в `/var/ledger.log`.

### Безопасность

| что могло пойти не так | как закрыто |
|---|---|
| Пополнение: между взглядом на слот и `pushItem` проходит тик, игрок успевает подложить в слот алмазы — и получил бы их число монетами | зачисляется не то, что ушло из инвентаря, а то, на сколько выросло число монет **в МЭ** (меньшее из двух); расхождение пишется в журнал |
| Покупка или снятие, а выдача оборвалась (полный инвентарь, выключение) | деньги списываются и пишутся на диск **до** выдачи; недоданное сразу возвращается на счёт |
| Питание пропало между удалением старого файла счёта и переименованием нового | при чтении подхватывается недописанный `<ник>.new` |
| Сигнал ухода с PIM потерялся, встал другой — покупку получил бы он | перед каждой операцией с деньгами магазин спрашивает у PIM, кто стоит; не тот — сессия закрывается |
| Чужой игрок жмёт по экрану, пока стоит другой | клики и клавиши не от того, кто на PIM, не проходят |
| Покупка по одной штуке дешевле на округлении | итог округляется вверх |
| Продажа монет как товара, предметов без цены | монеты на витрину не попадают, без цены в выгрузке — тоже |
| Выдали не тот экземпляр (с NBT вместо обычного или наоборот) | вещи с NBT выдаются по полному отпечатку с `nbt_hash`, каждая своей карточкой |

Что остаётся на совести владельца: вещь с NBT стоит как обычная. Броня с
улучшениями или предмет с дорогими чарами уйдут по базовой цене — такое в
МЭ магазина лучше не класть или выключить `sellNbt`.

## Файлы

```
/init.lua           ядро: видеокарта, require, перезапуск при падении
/sys/disk.lua       файлы поверх filesystem, чтение кусками по 2 КБ
/sys/gfx.lua        рисование: буфер видеопамяти, текст, иконки
/sys/catalog.lua    цена/название/иконка по ключу предмета
/sys/storage.lua    МЭ-интерфейс и PIM
/sys/wallet.lua     счета и журнал
/sys/shop.lua       экраны и логика магазина
/cfg/shop.cfg       настройки
/data/catalog.bin   каталог, часть 1
/data/catalog.2.bin каталог, часть 2 - на втором диске
/var/               счета, журнал, /var/crash.log
```

## Железо

| | |
|---|---|
| машина | сервер (или корпус) 3-го уровня: нужно **два жёстких диска** |
| видеокарта, монитор | 3-й уровень (экран 160×50: 8 карточек 32×32 на странице) |
| память | 1024 КБ хватает: в памяти индекс каталога (48 КБ), до 60 иконок и то, что есть в МЭ |
| диски | два по 4 МБ, без RAID: загрузочный (система, часть 1, счета) и второй (часть 2) |
| PIM | стоит на МЭ-интерфейсе: выдача `UP`, приём монет `DOWN` |
| интернет-карта | только на время установки |

## Установка

На машине с OpenOS и интернет-картой:

```bash
wget -f https://raw.githubusercontent.com/Faticc/shopos/main/install.lua /tmp/i.lua && /tmp/i.lua --clean
```

— машина перезагрузится сама (`--noreboot`, чтобы не надо).

Второй диск установщик находит сам (любой записываемый, кроме загрузочного
и tmpfs; `--disk2=адрес` — указать явно). Если его нет, установщик скажет
об этом до того, как что-то стереть. `--clean` стирает OpenOS и прежний ShopOS (`/os`). `--dry`
показывает, что будет записано. `cfg/shop.cfg`, если он уже есть на диске,
не перезаписывается — `--cfg` перезапишет его заводским. Каталог качается потоком прямо в файл — в память
машины он не поднимается.

## Проверка без игры

Из каталога `shopos/`:

```bash
lua test/run.lua out "on:Steve,coins:300,touch:150:2,touch:40:10,shot:item,touch:60:31,shot:bought"
```

```bash
python ../tools/renderscreen.py out/item.json item.png
```

`test/run.lua` — песочница OpenComputers без OpenOS, gpu с видеобуферами,
диск из этого каталога (чтение по 2 КБ, `/var` уходит в папку вывода) и
поддельные МЭ и PIM с теми же вызовами, что у модов. Сценарий с кириллицей
передавайте файлом: `@script.txt`.

```bash
lua test/install.lua out --clean --cfg
```

Прогон установщика на поддельной OpenOS: загрузочный диск с OpenOS и
остатками прежнего ShopOS, второй диск, tmpfs и дискета, каждый по 4 МБ с
отказом при переполнении. Ключ `nodisk2` убирает второй диск.

В стенде `test/run.lua` есть и попытки обмана: `evil` подменяет монеты
алмазами в момент `pushItem`, `ghost:Ник` ставит на PIM другого игрока без
сигналов.
