# ShopOS

Операционная система для OpenComputers, в которой ровно одна программа —
магазин с иконками предметов. Не надстройка над OpenOS, а её замена: своё
`/init.lua`, свой загрузчик модулей, своя файловая работа и своя база
игроков. Оболочки нет, поэтому выйти из магазина нечем.

## Установка одной командой

На машине с OpenOS и интернет-картой:

```bash
wget -f https://raw.githubusercontent.com/ВЛАДЕЛЕЦ/РЕПО/main/install.lua /tmp/i.lua && /tmp/i.lua
```

Затем `reboot` — и машина поднимается прямо в магазин.

Установщик можно посмотреть до того, как он что-то сделает:

```bash
/tmp/i.lua --dry
```

Ключи: `--repo=владелец/репо`, `--branch=имя`, `--disk=адрес` (ставить на
другой диск), `--token=файл` (приватный репозиторий), `--clean` (стереть
OpenOS), `--dry` (показать и выйти).

Ставить можно прямо поверх работающей OpenOS: ShopOS занимает `/os`, `/cfg`,
`/data` и `/var`, а из занятого OpenOS трогает только `/init.lua`, и то
последним. Пока файлы качаются, машина живёт на старой системе; новая
включается со следующей перезагрузки. Если загрузка оборвётся, `/init.lua`
останется прежним и машина загрузится как раньше.

## Что нужно на машине

| | |
|---|---|
| корпус | третьего уровня |
| видеокарта и монитор | третьего уровня (иначе иконки не на чем рисовать) |
| память | одна планка на 1024 КБ: иконки в памяти занимают 58 КБ, остальное — код и данные магазина |
| диск | любой: ShopOS целиком это 255 КБ, из них 74 КБ каталог иконок и 24 КБ список товаров |
| интернет-карта | только на время установки |
| PIM | вход игрока и выдача предметов |
| МЭ-интерфейс | склад магазина |
| database | четыре монеты-номинала в слотах 1–4 |

## Как это загружается

```
EEPROM (штатный Lua BIOS)
  находит на диске /init.lua, читает целиком, вызывает
      ↓
/init.lua — ядро ShopOS
  привязывает видеокарту, поднимает /os/fs.lua вручную,
  собирает require, io и сахар component.<тип>,
  запускает /os/shop.lua под присмотром
      ↓
магазин: свой цикл событий на computer.pullSignal
```

Дальше ядро только приглядывает. Если магазин упадёт, причина уходит в
`/var/shop.log`, на экран выводится трассировка, и магазин поднимается заново
с растущей паузой (1, 2, 4… до 30 секунд).

## Файлы

```
/init.lua              ядро: окружение, загрузка модулей, присмотр
/os/fs.lua             файлы поверх компонента filesystem
/os/event.lua          сигналы машины
/os/db.lua             счета и корзины игроков
/os/paint.lua          рисование иконок и текста, склейка вызовов gpu
/os/oci3.lua           чтение каталога иконок
/os/icons.lua          ключ предмета → иконка
/os/ui.lua             экраны, сетка иконок, кнопки, диалоги
/os/meio.lua           МЭ и PIM: выдача, приём, деньги
/os/shopcore.lua       баланс, покупка, продажа, обмен, корзина
/os/shop.lua           экраны магазина
/cfg/*.cfg             товары, курсы обмена, подстановки иконок, настройки
/data/icons.bin        каталог иконок, 74 КБ
/var/players/<ник>.lua счёт и корзина игрока
/var/shop.log          журнал сделок
```

Каталог `/os` выбран так, чтобы не пересечься с OpenOS: у неё заняты `/bin`,
`/boot`, `/etc`, `/home`, `/lib`, `/usr`.

## Чего в ShopOS нет — и почему это нужно

| нет | что это даёт |
|---|---|
| оболочки | из магазина некуда выйти: команду набрать негде |
| сигнала `interrupted` | Ctrl+C ничего не делает. В OpenOS этот сигнал придумывает сама `lib/event.lua`, глядя на зажатые клавиши; раз этого кода нет — нет и сигнала |
| процессов и сопрограмм | магазин это один цикл событий, планировщик и стеки сопрограмм ему не нужны |
| терминала | экран рисует сам магазин; буфер терминала на 160×50 — это 8000 ячеек в памяти впустую |
| `/etc/rc.d`, автозапуска | нечего запускать, кроме магазина |
| разбора командной строки, `man`, `edit`, `ls` | всё это некому набрать |

Единственный способ остановить машину снаружи — выключить её (или Ctrl+Alt+C,
это жёсткий сброс на стороне мода). И то, и другое приводит к выключенному
компьютеру, а не к приглашению оболочки: набрать там нечего.

## Настройка

`/cfg/shop.cfg` — название на экране, имя терминала в журнале, путь к
каталогу иконок, кому оставлять доступ к машине.

`/cfg/sellShop.cfg` — что магазин продаёт: `id`, `dmg`, `price`, `label`,
`category`, необязательный `nbt`. Категории собираются из этого файла в том
порядке, в каком встречаются, и становятся вкладками витрины.

`/cfg/buyShop.cfg` — что магазин скупает.

`/cfg/oreExchanger.cfg`, `/cfg/exchanger.cfg` — курсы обмена:
`fromId`/`fromDmg`/`fromCount` → `toId`/`toDmg`/`toCount`.

`/cfg/icons.cfg` — подстановки ключей, если каталог иконок выгружен с другой
сборки. Три вида правил: точный ключ, замена id с сохранением мета, замена id
с отбрасыванием мета.

Конфиги установщик не перезаписывает: если файл уже лежит на диске, он
остаётся как есть.

## Иконки

Каталог `/data/icons.bin` — формат OCI3 v2, только те предметы, что
упомянуты в конфигах. Пересобрать под свои конфиги:

```bash
lua tools/shopicons.lua большой-каталог.bin cfg cfg/icons.cfg data/icons.bin
```

Полный каталог сборки — 4.3 МБ и требует RAID из трёх дисков. Выборка под
магазин — 74 КБ, влезает на любой диск и поднимается мгновенно.

## Проверка без игры

```bash
lua test/shoptest.lua
```

Торговля на поддельных МЭ, PIM и базе: не только исходы операций, но и
сколько вызовов к моду ушло на каждую.

```bash
lua test/machine.lua out.json "on:Steve,touch:45:17,shot:buy"
```

Машина OpenComputers без OpenOS: песочница собрана ровно по списку из
`machine.lua` самого мода, BIOS читает `/init.lua` с каталога `shopos/` как с
диска, чтение режется до 2048 байт за вызов, как `maxReadBuffer` в конфиге
сборки. Смысл в том, чего там нет: обращение к `io`, `require`, `filesystem`,
`print` или `package` мимо ядра падает прямо в прогоне, а не на сервере.
`utf8` не выдаётся нарочно — в Lua 5.2 его не бывает.

События: `on:<ник>`, `off:`, `touch:X:Y`, `drag:X:Y`, `scroll:±1`,
`key:<символ>:<код>`, `shot:<имя>` (снять кадр).

## Ручная проверка в эмуляторе

[Ocelot Desktop](https://gitlab.com/cc-ru/ocelot/ocelot-desktop) поднимает
машину OpenComputers на ПК. Собрать корпус с видеокартой, монитором, диском и
EEPROM со штатным Lua BIOS, смонтировать каталог `shopos/` как диск,
включить — машина загрузится в магазин. PIM и МЭ эмулятор не даёт, поэтому
дальше экрана ожидания там не уйти; торговля проверяется `test/machine.lua`.
